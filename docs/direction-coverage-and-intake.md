# 按需求覆盖检索与一次理解（2026-10-16）

目标仍为准确、快速、节省额度的自然语言全站操控，未完成。
本阶段落实上一阶段两处缺口，不代表新推荐的同行计划、历史或分享已经接通。

## 代码与取舍

1. 本轮需求生成自由活动方向及对应地图/网页查询，不恢复固定六类。
   公共库分别检索各方向，先为每个方向保留位置，再容纳同方向后续候选；
   不能用“已有四个地点”判断所有方向都有资料。城市词只用于区域过滤，不能单独证明活动命中。
2. 缺口与联网预算分开：冷请求先一条，仍最多两次真实搜索。独立审查返回实际覆盖方向与
   通过的地点ID，未覆盖时精准补查；有卡片不等于整个需求完成。不得用宣传措辞拆出假多样性。
   同活动使用本轮经审查的方向名称，跨批次保持一致。既有卡片继续只追加、不重排。
3. 有公共资料时先整理首批，再执行新资料的提名；不因后续提名而等待所有候选。
   长篇合集中仅保留具体地点所在句及紧邻后文；实际引用也须含该实体，不能引用泛泛整篇。
   仍可能存在同名、子景点/父景点和现时服务的语义误判，未宣称程序能彻底消除。
4. 原规划步骤可同时提出11种当前结果/页面常见工具的完整业务方案。
   前端仅传入服务端保存的理解任务ID，仍走既有提案、权限、确认、对象绑定与执行日志。
   原话、来源job、焦点、选择、层级改变则拒绝复用；跨账户或过期任务无效。
   复杂业务仍回到完整规划器，没有裁掉原有功能目录。
5. 新增`compare_places`业务工具，一次绑定候选并打开比较，避免模型只选入却遗漏打开。
   全目录现61项（原60项保留）。旧查询和新查询的界面适配都支持这个完整任务。
   普通新查询不新增分类调用；常见操作可从两次模型变为一次，复杂操作仍可能两次。

本阶段参考[多查询检索研究](https://arxiv.org/abs/2402.03367)与
[Tavily官方查询实践](https://github.com/tavily-ai/skills/blob/main/skills/tavily-best-practices/references/search.md)。
使用现有SQLite索引及按方向保留名额，没有声称复现RRF排序或论文训练，也没有引入新框架、
向量服务、模型或收费服务。增加查询本身不保证质量，仍要验证具体对象和最终业务状态。
