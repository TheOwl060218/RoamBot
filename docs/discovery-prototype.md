# 开放休闲推荐原型 · 2026-10-15

本阶段在 `feat/conversational-business-tools` 分支新增独立 `/explore` 原型。
它用于检验新的推荐路线，尚未替换原 `/recommend`，也未部署。

## 已实现的范围

- 完整保留当次自然语言和最近对话，不再将需求压入旧六种景点类型。
- 地区、出发地、日期、路程上限均可缺省；有日期才查询天气，有中心才查询实际路线。
  明确出发地优先于授权定位，定位坐标通过高德转换；实际设备定位尚未验收。
- 地图检索不限景区类别，书店、展览、咖啡等可成为真实候选。
  不生成统一匹配指数，地图评分仅作为同类弱参考，未实现可靠的跨类型评分校准。
- 现有模型调用受限的只读业务工具，真实地点ID、证据归属、距离上限由程序核实。
- Tavily 基础搜索补充公开资料；网页先发现的资料在地图核实实体后复用，避免重复查找。
  搜索地区由当前上下文约束，资料不得来自不相关同名实体或泛化地区介绍。
- 逐个生成理由、引用真实出处，再由同一现有模型独立检查事实依据与需求匹配。
  这仍是概率性检查，不等于事实绝对正确。
- 卡片按自由命名的体验组穿插、分批追加；已出现的位置保持稳定。
  保留海边玻璃风格、整卡详情、独立出处链接、详情/地图浮层与可拖动聊天球。
- 作业按当前身份隔离，支持停止，保留数量/运行时间/工具预算上限；不写旧推荐数据库。

真实模式需要 `ROAMBOT_DISCOVERY_SEARCH_API_KEY`；未配置时明确返回503，
不回退到已经实测相关性差的公共RSS搜索。密钥不写入报告或版本库。
Tavily 使用 `basic`，每次搜索1 credit；检索费用不包含模型、高德和天气。
官方说明：https://docs.tavily.com/documentation/api-credits

## 真实链路结果：尚未通过推荐质量验收

实际模型保持现有配置，地图使用高德，公开检索使用用户授权的Tavily免费额度。

| 场景 | 实际结果 | 判断 |
| --- | --- | --- |
| Tavily密钥/基础搜索 | 请求成功，返回4条公开资料；仍混入无关页面 | 仅连接通过 |
| 苏州站出发，步行5公里内找草地或湖边放松 | 第一批65.3秒，最终83.7秒，仅1项；6次搜索 | 数量、速度、语义未通过 |
| 苏州独立书店，可翻摄影集和坐一会儿，不要商场 | 80.4秒、0项、6次搜索；模型虽finish，业务验收失败 | 未通过 |
| 草地/湖边原句，证据复用后的复验 | 98.5秒、0项、10次搜索 | 未通过，保留失败 |
| 实际8033 HTTP会话：苏州好玩的地方，给不同体验 | 首批92.7秒，总计110.3秒、2项（拙政园/平江路）；无日期/出发地时route/weather均为空 | 接口串联通过；速度和数量未通过 |

发现模型仍可能把类别当作设施事实、把相似体验当作满足原意，也会调用预算外工具。
审查确实挡住了部分无依据理由，但没有保证开放语义准确。
原型的首批延迟、候选召回、公开中文长尾地点资料覆盖，仍是核心问题。

失败后实际修复：保留网页→地图证据、地区约束、精简工具返回且保持完整JSON及所有实体、
跳过路程超限地点的资料搜索；移除“首批前搜过两次就不许再查地图”的限制，
它会阻断后续从公开资料发现的新地点。最终改动的验证另见交接最新补充。
最后移除地图首批前次数限制的改动仅做定向自动回归，并已更新本地服务；
上述HTTP真实报告产生于移除该限制前，没有把该报告冒充最终改动的Live复验。

## 尚未接入或验收的部分

- 新结果未接入旧收藏/历史/比较/建计划的快照合同。旧业务聊天与按钮继续在原页面使用，
  不能声称新原型已经完整支持所有后端操作。
- 不做长期个人画像或针对个别原句的特殊记忆；个性化目前限本次对话。
- 地图周边检索上限50km；大范围召回尚未完成区域拆分/分页与覆盖验证。
- 地点可进入性、实际草地、安静程度等公开资料可能缺失；不能依据“公园”或“有地址”补造。
- 现有免费搜索只用于限定验收。持续使用前还需搜索缓存、用量统计和跨场景质量评估。
- 未部署Railway，未更换模型，未操作8026，未改比赛归档及共享工作区。

本地体验入口为 `http://localhost:8033/explore`。当前启动的是有未提交改动的分支快照；
运行元数据记录实际前端资源名与推荐服务源文件哈希，避免只用HEAD判断运行版本。

## 后续阶段：批量工作流与短时缓存

本阶段用户批准提速。`/explore`真实路由已切换到`DiscoveryWorkflow`，保留原只读代理
作为早期原型和既有合同测试，真实推荐不再运行最多16轮的自由工具循环。

执行顺序：一次检索规划→程序并行检索→一次集中地点提名→核实真实地图实体→
按批取得路线/天气→批量生成理由→独立核验→发布。首批最多4个候选，后续每批最多6个。
网页发现地点需要集中提名，因此冷首批一般仍有4次模型调用；不能宣传成只有2次。
不切模型、不去掉程序校验或独立理由核验。

缓存使用独立`discovery-facts.sqlite3`，按已验证的会话身份隔离，不与业务写事务共用文件。
网络请求不持有数据库事务或缓存全局锁；同一键并发只请求一次，失败与空结果不缓存。
容量最多2000条，键为摘要，不保存密钥、Cookie或鉴权token。

| 内容 | 有效期/失效条件 |
| --- | --- |
| 地图地点搜索 | 24小时；地区、中心、半径、检索词均参与键 |
| 公开资料片段 | 6小时；范围和检索词参与键 |
| 实际路线 | 5分钟；地点ID、起终点和方式参与键 |
| 天气 | 10分钟；地点坐标及日期参与键 |
| 检索计划、地点提名 | 5分钟；当前中国日期、原话/最近对话、当前条件、模型和资料输入参与键 |

最后一项是短时复用同一次请求的中间结果，不是长期个人偏好；最终理由始终重新生成。
改日期时复用原地点并查新天气，改出发地或方式时重算路线；可选字段的null不再隐式清空旧条件。
明确清空或改变出行方式仍需原话依据。新GPS坐标会替换旧定位，明确出发地优先。

Tavily默认使用查询相关片段，不拉整页；每轮最多3条初始搜索，显示实际返回的usage。
地图请求跨作业限速，避免并发突发；地点名称与ID必须同时核实，错配不能静默合并。
短出处编号减少模型抄写长URL的开销，程序负责绑定原始出处；未知ID/URL不能作为证据。
