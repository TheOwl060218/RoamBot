# 无鼠标操作标准与当前证据

## 用户目标

验收对象是已有用户能力的替代操作入口：不要求先按指定流程点击、不要求先进入某页；用户可以用聊天表达查询、修改、对象选择、跨页操作、返回和确认。验收不能由测试代码替用户点开入口。

`Alt+/` 在任何站内页面聚焦当前可交互聊天；收起的球会展开，嵌套浮层只操作当前层。密码不发送给模型：对话打开登录/注册后，用 Tab 在安全表单中输入并回车提交。

## 本轮实际修复

- 聊天唤起、跨页/浮层后的焦点归还；组件卸载时取消旧焦点任务，避免抢占新页面。
- “更多功能”内补入聊天入口和关闭动作；推荐偏好、收藏选件、同行挑选/退出均有显式动作。
- 计划详情和账号初始加载完成后才提出方案，避免页面自动载入被误判为用户改动。真正的手动改动仍按版本拒绝旧方案。
- 首页发出注册指令时，等待账户动作注册再打开表单，修复跨页事件丢失。
- 当前账号的具名计划/历史/收藏提供受限摘要给模型；邀请、投票、天气和定案可显式绑定具名计划，不强迫先导航。
- 离开推荐页后保留同一账号、同一历史/结果版本的选择；最近查询上下文供跨页继续任务，重新进入推荐后先绑定请求再应用条件响应。
- 追问使用最近的全局对话，避免旧推荐对话盖掉刚发生的追问。
- 计划解读使用服务端已授权快照与最新天气；不借用旧推荐事实，也不恢复计划中已去除的个人出发路线。
- 新增地图缩放、平移、重置、重试，页面/横向列表滚动、聊天记录滚动，生成链接的站内打开，以及实际能力说明。

工具注册表目前共60项，保留原按钮。模型负责选择业务动作，程序负责授权、对象绑定及实际执行。

## 验收方式

1. `mouseless-business.spec.ts` 从空白会话开始，仅用键盘和聊天唤起、注册、填写条件、查询、滚动、收藏、选择、详情、地图、返回、去收藏后返回、创建计划、输入确认生成邀请。监听并断言 pointerdown=0。
2. `business-commands.spec.ts` 验证实际 Mock API 最终收藏ID、仅一项计划、改名和真实生成链接，当前也使用快捷键进入聊天。
3. 两种场景各覆盖桌面1440×900、手机宽度390×844及减少动画模式。类型、规范及生产构建独立执行。
4. `keyboard-live.spec.ts` 只在显式授权开关下执行，真实模型用独立表达询问能力、跨页打开功能、关闭功能、进入注册；仅键盘，pointerdown=0。正常测试默认跳过，避免消耗真实额度。
5. 后端覆盖跨页面具名计划及越权拒绝、计划事实不混入旧查询、原有并发/CSRF/重试/未知提交/澄清终止检查。

结果及当前构建资源记录在 `conversational-business-acceptance.md`。上述是实际执行过的有限场景，不应描述成60项所有语言表达均已通过。

## 尚未充分证明的部分

- 地图命令已通过模拟 SDK 的缩放/平移/重置回归；真实 SDK 下这些命令尚未逐项验收。
- 本轮真实模型浏览器覆盖4个独立意图，不代表所有计划、邀请、删除等动作全部完成全 Live 浏览器无鼠标验收。
- 第三方高德页面、浏览器权限对话框属于浏览器/第三方交互范围；应用不能用自身聊天越过浏览器权限。
- 真机与Safari未实测，开放表达仍可能理解错误或遇到模型网关超时。
- 手动通过原按钮打开的原生创建计划表单等界面，仍保留键盘操作；这些中间表单未逐项验证可在其中继续聊天。对话可以直接完成对应业务，但不能据此把所有中间界面的聊天可达性标为通过。
