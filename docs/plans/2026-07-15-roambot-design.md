# RoamBot 完整设计基线

日期：2026-07-15  
状态：已由用户批准

## 1. 目标

RoamBot 是一个天气感知的风景出行推荐 Web 应用。用户提供出发地、未来日期、最大距离和风景偏好，系统结合地点、天气、距离与热度生成可解释的推荐；用户也可以直接评估一个指定地点。

个人用户是核心场景。额外支持最多两个同行人地址，用距离差异衡量汇合公平性。正式作业先交付响应式 Web；微信小程序只在 Web 项目全部验收完成后另行评估。

## 2. 范围边界

当前范围：

- 推荐模式和指定地点评估模式。
- 高德地点、POI 与距离数据。
- QWeather 未来七天逐日天气。
- 确定性评分与可选 LLM 自然语言解释。
- 游客核心查询。
- 本地账户、收藏、历史快照和匿名只读分享。
- SQLite 持久化、Docker 分发和 GitLab CI。

明确不做：

- 地图展示、路线绘制、导航和逐日行程安排。
- 12306、机票、社交动态、评论和第三方登录。
- 邮箱验证、密码找回、数据导出和账户注销。
- 手机号收集、短信验证码，以及图片、滑块或云验证码服务。
- 将 LLM 用作评分器、分类器或自主工具调用 agent。

## 3. 总体架构

源码采用前后端分离结构：

- `frontend/`：React + TypeScript + Vite，负责页面、交互和客户端状态。
- `backend/`：FastAPI，负责认证、推荐、评分、外部 provider、SQLite、凭据和授权。
- 评分与资源权限规则只存在于后端，前端不得复制。

开发时 Vite 与 FastAPI 分别运行，Vite 代理 `/api`。生产时先构建 React，再将静态产物与 FastAPI 打入同一个 Docker 镜像，通过同一域名提供 `/` 和 `/api/v1`，不拆成两个云服务。

SQLite 数据库、加密凭据库和外部 API 缓存放入持久化数据卷。

## 4. WebUI V1

第一屏直接提供推荐工具，不制作营销落地页。顶部导航包含推荐、收藏、历史和账户入口。

桌面端使用输入区与结果区左右布局；手机端改为上下布局。推荐模式与指定地点评估模式使用分段控件切换。

输入包括：

- 主出发地和最多两个同行人地址。
- 最大距离与未来七天内的日期范围。
- 推荐模式下的风景类型多选和覆盖模式。
- 指定地点评估模式下的目标地点。
- 可调权重分段滑块，自动归一化到 100%。

结果卡片包括：

- 地点名称与风景标签。
- 总推荐分与分项评分。
- 距离、多人公平性和每日天气适宜度。
- “RoamBot 热度估算”标记。
- 推荐理由、风险、缓存/演示/降级来源状态。
- 收藏、历史详情和分享操作。

该页面结构是 V1 基线。开发服务器运行后可继续调整布局、视觉和交互，但不得改变已确认的数据语义或在前端复制评分逻辑。

## 5. 请求数据流

推荐模式：

1. 校验输入并解析 1-3 个出发地址。
2. 通过高德 POI 检索获取候选地点。
3. 根据 POI 类型、名称关键词和人工修正规则生成风景标签。
4. 使用坐标粗筛，再对少量候选查询精确距离。
5. 对筛选后的候选查询 QWeather 逐日天气。
6. 在后端计算天气、距离、公平性与热度分。
7. 执行硬过滤并按用户权重排序。
8. 最多一次批量 LLM 调用生成顶部结果解释；失败时使用模板。
9. 返回结果；登录用户成功查询写入历史，游客不写入。

指定地点评估模式直接解析目标地点，不执行候选列表检索和排序，其余评分模块复用。

历史重新查询重新进入当前数据流并创建新记录；分享只读取脱敏历史快照，不调用外部 API。

## 6. 风景分类与热度

内部风景类型为湖景、海景、古镇/历史街区、博物馆、公园/绿地/湿地、山地/徒步。

分类优先级：

1. 高德 POI `type` / `typecode`。
2. 地点名称关键词补充。
3. 少量可审查的知名地点人工修正。

地点可以具有多个标签。不能可靠识别时标记未知，不交给 LLM 猜测。分类映射独立配置并由测试保护。

高德未稳定提供统一景点数字热度时，将 POI 综合搜索排名转换为基础分，并允许少量本地修正。界面始终称其为“RoamBot 热度估算”，不得冒充高德官方评分。

## 7. 评分

所有分项限制在 0-100。

硬约束：

- 推荐模式下风景类型必须匹配。
- 候选不得超过用户最大距离。

每日天气分使用确定性规则考虑降雨、温度、风力、能见度及不同风景类型的敏感度。具体阈值属于实现配置，必须有边界测试和可解释扣分原因。

多日天气分：

```text
每日适宜度平均分 × 70% + 最差一天适宜度 × 30%
```

单人默认权重：

```text
天气 40% + 距离 30% + 热度 30%
```

多人默认权重：

```text
天气 40% + 公平性 40% + 热度 20% + 距离 0%
```

用户可以调整全部可见权重，系统自动归一化。多人公平性由各出发地距离差异/方差决定；平均距离和最大距离用于解释，整体远近由独立距离分表示。

## 8. Provider、缓存与降级

外部 provider：

- 高德：地理编码、POI 检索、分类来源和距离。
- QWeather：未来七天逐日天气。
- OpenAI-compatible LLM：默认演示模型为学校平台 DeepSeek V4 Flash，仅生成解释。

建议缓存基线：地址 30 天、POI 7 天、距离 1 天、天气 1 小时；具体 TTL 为可调配置。

失败处理：

- 地址解析失败：提示修正输入，不继续调用后续 API。
- POI 失败：可用同范围未过期缓存并标注来源。
- 距离失败：可降级为明确标注的直线估算。
- 部分天气失败：不为缺失天气的地点生成完整推荐分。
- 所有天气失败：请求失败且不写历史。
- LLM 失败：使用模板解释，不影响确定性评分。

内置苏州数据只允许管理员显式开启演示模式时使用，页面持续标注“演示数据”。正式模式无有效缓存时不得静默返回内置地点。

测试和 CI 的真实调用数为零。真实请求限制候选数量、精确距离/天气查询数量和 LLM 次数；具体上限作为实现配置并通过测试验证。

## 9. API 契约

JSON API 使用 `/api/v1`：

- `POST /recommendations`
- `POST /place-evaluations`
- 注册、登录、退出和当前用户状态接口。
- 收藏的读取、添加和删除接口。
- 历史列表、详情、删除、清空和重新查询接口。
- 分享创建、撤销和匿名读取接口。

推荐与指定地点使用独立入口，内部共享领域服务。统一错误响应包含稳定错误码、用户可读消息和必要字段错误，不泄露堆栈、内部路径或敏感数据。

## 10. 账户与数据安全

账户使用唯一用户名和密码。密码只保存成熟库生成的安全哈希。

登录使用服务端会话与 `HttpOnly` Cookie，生产启用安全 Cookie 属性，状态修改请求使用 CSRF 防护。后端对收藏、历史和分享逐次验证资源归属。

收藏只保存地点关联；重新打开时要求新的出发地和日期。历史只保存成功查询的输入、生成时间和结构化结果快照。删除历史会使关联分享失效，不影响收藏。

分享令牌不可猜测，数据库只保存令牌哈希；公开快照移除身份和详细出发地址。

高德、QWeather 和 LLM key 保存在带主密码的认证加密凭据库中。管理入口仅存在于本机管理员 CLI；公开 WebUI 不允许初始化、更新、清除或重置凭据。

忘记主密码时，拥有 Docker 主机权限的管理员可不可逆重置凭据库并重新录入 key；SQLite 用户数据不删除，旧 provider key 仍需在供应商控制台撤销。

## 11. 凭据申请时机

设计、项目骨架、评分、provider 接口和自动测试阶段全部使用 mock，不需要真实凭据。

只有 provider 适配器和 mock 测试通过、准备执行人工真实 API 冒烟测试时，用户才申请凭据并通过本机隐藏终端录入。真实 key 不发送到聊天，不进入源码、`.env`、Git、Docker 镜像或 CI。

## 12. 测试与交付

自动测试：

- pytest：校验、评分、provider 适配、认证、授权、持久化和降级。
- Vitest：模式切换、表单、权重、结果卡片、来源状态和登录状态。
- Playwright：游客推荐、注册登录、收藏、历史重查、匿名分享，以及桌面/手机无重叠。

真实 API 冒烟测试是独立管理员命令，使用固定苏州小样本并记录 provider 调用次数，不属于默认测试或 CI。

Docker 使用多阶段构建生成单镜像，并通过数据卷持久化 SQLite、缓存和加密凭据库。镜像发布到公开 registry。

GitLab CI 至少包含 `unit-test` job，运行自动测试和构建检查，不注入真实 key。

最终证据包括 `SPEC.md`、`SPEC_PROCESS.md`、`PLAN.md`、`AGENT_LOG.md`、`REFLECTION.md`、测试结果、CI 记录、Docker 说明和桌面/手机界面截图。

## 13. 实现时可调但不得越界的参数

- 每日天气扣分阈值。
- 缓存 TTL。
- 单次请求候选与 provider 调用上限。
- V1 的颜色、间距、布局细节与结果展开方式。

这些参数可通过测试和实际体验迭代，但不得取消来源标记、硬约束、隐私保护、零真实调用 CI 或已确认的产品范围。
