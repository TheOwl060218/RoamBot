# RoamBot 暑期任务：学生本人完成清单

> 本清单只列必须由学生本人完成、确认或承担责任的事项。技术命令、事实整理和文字润色可以由 AI 辅助，但不能让 AI 替代个人判断、真实操作或反思正文。

## 一、必须由本人撰写

- [ ] 用自己的语言完成 `REFLECTION.md`，正文为 1500-2500 字。
- [ ] 删除当前文件中的写作提示，只保留自己形成的正文和标题。
- [ ] 写出真实的个人判断，而不是只介绍工具：哪些 Superpowers 技能有用、哪些形式大于实质、审查为什么一度过量、TDD 在哪些场景有价值、如果重做会怎样调整。
- [ ] 至少使用一个亲历案例说明 SPEC/PLAN 不清导致的问题，以及一个 RED-GREEN 或回归测试案例。
- [ ] 在文末如实写 AI 辅助声明：AI 参与了需求澄清、计划、编码、测试和事实整理；反思观点与正文由本人完成。若最后让 AI 润色，应说明只做了语病或结构润色。

作业明确禁止 AI 代写反思。AI 可以在你写完后指出语病、重复和结构问题，但不应替你生成可直接提交的正文。

## 二、必须由本人核对并承担责任

- [ ] 通读 `SPEC.md`、`PLAN.md`、`SPEC_PROCESS.md`、`AGENT_LOG.md`、`README.md`，确认其中的需求、决策、测试结果和时间记录真实，没有把“计划执行”写成“已经执行”。
- [ ] 确认你能当面解释：项目解决什么问题、为何不做地图/导航/行程安排、评分怎样计算、Mock 与 Live 有何区别、为何使用加密凭据库、Docker 数据卷保存什么。
- [ ] 亲自确认所有界面和功能达到你认可的程度；AI 的自动测试通过不能替代你的验收判断。
- [ ] 对课程要求与实际流程的偏离作出自己的解释。例如前期陌生 agent 和逐 task 审查明显过量，后来改为大里程碑集中检查；这应如实写进过程记录和反思，而不是隐藏。
- [x] 检查最终文档中的“游客能否直接查询”表述是否与最终实现一致：游客可以直接使用推荐和指定地点评价；收藏、历史、重新查询和个人分享管理等个人数据功能需要登录。该口径已与 `SPEC.md`、`README.md`、后端路由和游客端到端测试核对一致。

## 三、必须由本人执行的账户与凭据操作

- [ ] 保管高德、QWeather、学校 LLM 的真实 key、QWeather API Host 和 RoamBot 主密码；不要粘贴给任何 AI，也不要写入仓库、聊天、截图或普通配置文件。
- [x] 在 Railway 上创建账户、确认试用额度、配置 secret 和持久化存储；这些本人操作已经完成。
- [x] 公网部署使用 Live 模式，真实凭据已通过 Railway secret 录入；现有脱敏日志与页面检查未发现 key 回显。
- [ ] 若遗忘凭据库主密码，只能 reset 后重新录入并撤销旧 key；不要尝试把真实 key 交给 AI 排错。

## 四、最终人工验收

- [ ] 用最终构建版本在桌面端和手机宽度各完成一轮主流程：登录、推荐、指定地点评估、收藏/取消收藏、历史、重新查询、分享/撤销、删除历史。
- [ ] 使用浏览器无痕窗口打开分享链接，确认无需登录且不含用户名、详细出发地、Cookie 或凭据。
- [ ] 至少检查一个单日、一个多日、一个多人、一个跨城市、一个异常输入场景。
- [ ] 若最终代码仍修改了后端 provider 或推荐逻辑，再进行一次小样本 Live smoke；记录真实调用次数和结果，不需要反复消耗额度。
- [ ] 保存必要的脱敏截图或简短录屏作为演示证据；不得出现 API key、主密码、Cookie、完整个人地址或账户敏感信息。
