# RoamBot 统一前端体验设计

日期：2026-08-01

## 1. 背景与目标

RoamBot 已完成推荐、指定地点评估、账户、收藏、历史、分享和外部 Provider 接入。当前主要问题不在功能缺失，而在信息结构和视觉语言不统一：桌面端查询条件与结果区域左右失衡，结果卡纵向过长，手机端信息堆叠，历史和收藏页面操作入口分散，不同按钮、弹窗和状态提示缺少一致的形态规则。

本设计在不扩大产品边界的前提下完成一次集中前端重构，目标如下：

- 建立安静、简约、可扩展的全站视觉系统。
- 解决桌面端左右失衡和超长页面问题。
- 为手机端建立独立的信息顺序与候选切换方式，而不是压缩桌面布局。
- 统一推荐、历史、收藏、账户和确认交互。
- 保留已经通过人工测试的功能、状态恢复和错误处理行为。
- 将视觉验证集中在完整页面和主要工作流，避免重复的小规模审查拖慢进度。

## 2. 范围与非目标

### 2.1 本次包含

- 推荐页查询前、查询后和指定地点评估模式的布局。
- 桌面端候选列表与地点详情双栏工作区。
- 手机端候选列表、顶部切换器和候选抽屉。
- 单日和多日天气展示。
- 湖光蓝品牌体系、文字层级、间距、边框和按钮规则。
- 历史、收藏、账户弹窗和确认弹窗的统一排版。
- 桌面、平板和手机响应式适配。
- 鼠标、触摸和键盘的完整按钮状态。
- 现有自动化测试的适配，以及集中式视觉验证。

### 2.2 本次不包含

- 地点图片、图片蒙版或新的图片 Provider。
- 地图、路线绘制、导航或行程安排。
- 新的第三方 API 或现有 API 调用预算调整。
- 推荐算法、评分公式或候选筛选规则调整。
- 全新的加载动画或新的顶部提示机制。
- 小程序实现。

第一版不展示地点图片，也不保留空图片区。未来若重新讨论图片，应作为独立设计和实施任务处理。

## 3. 设计原则

1. **中性色承载内容，品牌色表达操作。** 页面和正文以中性色为主，湖光蓝仅用于主操作、选中状态和出游匹配指数。
2. **颜色不单独传递含义。** 适合、谨慎和不建议状态始终同时提供文字和图标。
3. **先比较，再深入。** 候选列表只提供比较所需摘要，完整信息放入地点详情。
4. **手机端按阅读顺序重排。** 不压缩双栏，不使用多日天气横向滚动，也不设置页面内部滚动区。
5. **状态变化不改变布局。** 错误、加载、按钮按压和提示出现时不推动相邻内容。
6. **同类操作使用同一种反馈。** 全站按钮共享默认、悬停、按下、聚焦、加载和禁用状态。

## 4. 视觉系统

### 4.1 色彩角色

以下色值是本次浅色主题的基准值。实现时以语义变量引用，不在组件内重复硬编码。

| 角色 | 建议值 | 用途 |
| --- | --- | --- |
| `--color-page` | `#F5F7F6` | 页面背景 |
| `--color-surface` | `#FFFFFF` | 表单、列表、详情和弹窗表面 |
| `--color-text-primary` | `#18201D` | 标题、地点名和关键结论 |
| `--color-text-secondary` | `#4F5C57` | 正文和推荐理由 |
| `--color-text-muted` | `#66716C` | 地址、来源、时间和辅助标签 |
| `--color-border` | `#D7DEDA` | 分隔线和常规边框 |
| `--color-brand` | `#176F8A` | 主按钮、选中项、当前导航和指数 |
| `--color-brand-strong` | `#125B72` | 品牌色文字、悬停和按下状态 |
| `--color-brand-soft` | `#E5F2F5` | 选中项和轻量品牌背景 |
| `--color-positive` | `#176143` | 适合前往 |
| `--color-positive-soft` | `#E8F4ED` | 适合状态背景 |
| `--color-warning` | `#84550F` | 谨慎考虑 |
| `--color-warning-soft` | `#FFF4DC` | 谨慎状态背景 |
| `--color-danger` | `#A63D32` | 不建议和破坏性操作 |
| `--color-danger-soft` | `#FFF0EE` | 不建议状态背景 |
| `--color-info` | `#315A7D` | 数据来源、缓存和降级信息 |

普通正文与背景的对比度不得低于 4.5:1；大号文字、焦点轮廓和关键非文字控件不得低于 3:1。禁用状态可以降低强调度，但不能与可用状态混淆。

出游匹配指数始终使用湖光蓝，不随数值高低变红或变绿。指数只用于比较本次候选地点；能否前往由独立状态栏表达。

### 4.2 字体层级

| 层级 | 桌面端 | 用途 |
| --- | --- | --- |
| 页面标题 | `28px / 36px`, 700 | 推荐、收藏、历史页标题 |
| 地点标题 | `22px / 30px`, 700 | 当前地点名称 |
| 分区标题 | `18px / 26px`, 600 | 天气、推荐理由、候选列表 |
| 正文与数据 | `16px / 25px`, 400-600 | 正文、状态、关键数值 |
| 辅助文字 | `14px / 21px`, 400 | 地址、来源、保存时间 |

手机端可以在固定断点缩小页面和地点标题，但正文不得低于 15px。字号不随视口宽度连续缩放。字间距保持为 0。只有标题、结论和关键数值使用粗体，不将整段建议设置为粗体。

### 4.3 边框、圆角和层级

- 页面区域依靠留白、细分隔线和表面层次组织，不使用大面积同色填充。
- 信息面板、输入框和弹窗使用 6-8px 圆角。
- 不创建卡片套卡片；候选条目和历史行属于列表行，而不是独立漂浮卡片。
- 阴影仅用于弹窗、抽屉和需要覆盖页面的浮层；普通面板不使用明显阴影。
- 同层级组件使用相同边框和间距，不在不同页面创造新的局部风格。

### 4.4 图标

- 统一使用现有 Lucide 线性图标。
- 天气代码映射到 `Sun`、`CloudSun`、`Cloud`、`CloudRain`、`CloudLightning`、`Snowflake` 和 `CloudFog` 等图标。
- 不使用 emoji 表达天气或操作。
- 不熟悉的纯图标操作提供 tooltip，并支持鼠标、键盘和触摸访问。

## 5. 按钮与交互状态

### 5.1 形态

- 文字按钮和图标加文字按钮使用胶囊形。
- 纯图标按钮使用圆形，避免无意义的横向空白。
- 主操作使用湖光蓝实心按钮。
- 次操作使用白色表面、细边框和一级文字。
- 危险操作只在溢出菜单和确认弹窗中使用砖红色。
- 输入框、卡片、弹窗和历史行不采用胶囊形。

本设计只采用胶囊按钮外形，不引入类似“灵动岛”的伸缩、变形或黑色悬浮外观。

### 5.2 状态

所有按钮必须实现同一套状态：

- 默认：正常颜色和边框。
- 悬停：背景或边框轻微加深。
- 按下未松开：立即加深颜色，并通过 `transform: scale(0.98)` 表达按压；不得改变按钮占位尺寸。
- 松开、取消或指针移出：平滑恢复。
- 键盘聚焦：显示清晰、满足对比度的焦点轮廓。
- 加载：沿用当前加载反馈，保持控件尺寸并禁止重复提交。
- 禁用：降低强调度，取消悬停和按压反馈。

按下状态必须同时适用于鼠标和触摸。键盘触发需要提供等价的激活反馈。

顶部成功、失败提示和查询进度继续使用当前机制。本轮只统一其字体、颜色、边框和间距，不改写动画或数据流。

## 6. 全站结构与导航

- 顶部导航在推荐、收藏和历史页面保持相同高度、边框和激活状态。
- 页面内容设置最大宽度，在超宽屏中保持稳定阅读宽度。
- 推荐、收藏和历史复用相同的页面标题、工具区和空状态结构。
- 登录、确认和账户弹窗共享遮罩、标题、关闭、Esc、焦点管理和操作区规则。

## 7. 推荐页

### 7.1 查询前

- 使用单列、居中的完整输入表单。
- 保留现有推荐与指定地点评估分段控件，以及原有字段组织方式。
- 不改变三段权重条、两处分界控制和多人固定公平权重的产品约定。
- 输入行的错误区域预留稳定高度，错误出现时不改变相邻输入框尺寸。

### 7.2 查询后桌面端

查询成功后，完整表单收为查询摘要栏。摘要显示城市、日期、出发地数量、类型和权重概览，并提供“修改条件”胶囊按钮。展开修改时在原位置恢复表单，不跳转页面。

主结果区采用等高双栏：

- 左侧为候选列表。
- 右侧为当前地点详情。
- 两栏在可用视口高度内分别滚动。
- 默认选择第一个候选地点。
- 点击其他候选只替换右侧内容，不改变页面宽度或滚动到新页面。
- 新查询完成后选择新结果的第一项。
- 从历史、收藏或其他页面返回时恢复离开前的选中地点。

### 7.3 候选列表

候选列表每行只显示：

- 排名。
- 地点名称和类型。
- 出游匹配指数。
- 距离与地点评分。
- 一句天气状态摘要。

列表不显示完整逐日天气和推荐理由。选中行使用湖光蓝左侧强调线与浅品牌背景，不依赖整行高饱和填色。

### 7.4 地点详情

地点详情按以下固定顺序排列：

1. 地点名称、类型、地址和收藏按钮。
2. 出行建议状态与出游匹配指数。
3. 天气适配、路程体验、地点评分和多人路程差异。
4. 各出发地的驾车距离与预计时间。
5. 单日或多日天气与出行提示。
6. 推荐理由。
7. 数据来源和计算口径。

单人出行不显示“平均路程”、同行或多人差异。多人差异继续使用相对比例判断，并显示“差异很小、差异较小、差异较大、差异很大”四档。

### 7.5 手机端候选切换

手机和平板使用单列自然滚动：

1. 查询摘要。
2. 紧凑候选列表。
3. 当前地点详情。

候选列表滚出视口后，在顶部导航下方显示紧凑地点切换器，例如 `‹ 1/5 · 苏州博物馆 ›`。

- 左右按钮依次切换地点。
- 点击中央地点名称，从底部打开候选抽屉。
- 抽屉使用与初始候选列表相同的精简行，不引入另一套信息结构。
- 选择地点后关闭抽屉，替换详情并保持当前阅读位置。
- 候选列表始终留在文档流中；切换器通过观察列表是否离开视口显示，不删除列表，因此不造成滚动位置跳变。
- 当用户滑回候选列表区域时，顶部切换器自动消失。

手机端不设置候选列表或详情内部滚动区。

## 8. 天气与推荐文案

### 8.1 单日与多日

- 单日查询保留完整的单日天气面板。
- 多日查询使用逐日信息行，不使用横向滚动，不出现五日数据 `4 + 1` 的孤立换行。
- 每日行包含天气图标、中文日期、天气、带提示词的温度、出行状态和建议。
- 日期显示为“7月25日”，温度显示为“温度 27-37°C”。

### 8.2 文案长度

天气建议按风险分级控制：

- 适合前往：通常 8-18 个汉字，只保留行动建议，例如“往返途中注意防晒。”
- 谨慎考虑：说明主要影响并给出可执行建议，可以使用一个完整句子。
- 不建议前往：允许一至两句，明确风险来源、受影响日期以及调整日期或改选室内地点等替代方案。

删除“室内参观受高温影响较小”等显而易见的原因解释，但保留“往返途中注意防晒”等实际建议。文案不得重复已经展示的日期、温度和内部扣分值，也不得出现未经数据支持的“湖景优美”“必去”等表述。

## 9. 数据来源与降级信息

结果区域统一显示一次以下信息：

> 天气数据来自和风天气；地点评分来自高德开放平台；距离与用时按查询时驾车路况估算；出游匹配指数仅用于比较本次候选地点。

- 数据说明位于结果摘要下、候选与详情工作区上方。
- 桌面端可以为单行，手机端允许自然换为两行。
- 正常新鲜缓存命中不显示技术提示。
- 旧缓存、直线估算或 Provider 降级使用独立提示，不混入正常数据说明。
- 降级提示说明用户需要知道的影响，不显示内部实现字段或错误堆栈。

## 10. 表单状态与地址候选

- 推荐与指定地点评估切换时，共用字段保持不变，独有字段分别保存。
- 从推荐进入收藏、历史、账户或详情再返回时，恢复当前标签页内的表单草稿、最近结果和选中地点。
- 返回推荐页不自动重新请求 API。
- 登录弹窗关闭、成功登录、成功注册或退出登录后清空用户名、密码、错误和显示密码状态。
- 敏感登录状态的清理不得复用或破坏推荐表单状态恢复逻辑。
- 地址候选只在对应出发地输入框获得焦点并发生用户编辑后显示。
- 单独修改城市不得弹出旧的出发地候选。
- 地址候选优先使用已填写城市，但允许自由文本和跨城市出发地。
- 候选接口失败时隐藏候选列表，不阻断提交。

## 11. 历史页面

历史页面采用 Rows 式紧凑记录行，不再使用高卡片加一排等权按钮。

每行显示：

- 查询类型与城市。
- 日期范围。
- 结果数量。
- 保存时间。

整行点击查看历史快照。重新查询、创建或复制分享、撤销分享和删除收进右侧 `···` 菜单。菜单项根据当前分享状态变化，不在记录行中保留空白状态区域。

- 桌面端按列对齐。
- 手机端转换为两行摘要，并在右侧保留 `···`。
- 清空历史作为页面级操作保留在标题区。
- 删除、撤销分享和清空历史使用站内确认弹窗。
- 历史重新查询继续使用现有即时请求锁和加载反馈，防止重复记录。

## 12. 收藏页面

### 12.1 桌面端

- 左侧为紧凑收藏列表，右侧为当前收藏地点详情。
- 默认选择第一个收藏地点。
- 点击其他收藏地点只替换右侧详情。
- 空状态占据完整工作区，并提供返回推荐页的主操作。

### 12.2 手机端

- 先显示收藏列表。
- 点击收藏项进入完整详情视图。
- 返回列表时保持原滚动位置。

### 12.3 收藏交互

- 未收藏为空心星，已收藏为同尺寸黄色实心星。
- 再次点击已收藏星取消收藏。
- 收藏和取消操作期间锁定按钮，失败时恢复原状态。
- 收藏列表只显示地点名称、类型、城市和评分。
- 详情显示已有地址、类型、评分来源和重新评估入口，不接入图片或新的详情 API。

## 13. 账户、弹窗与反馈

- 登录、注册、账户和确认弹窗使用相同标题区、内容间距和操作区。
- 支持 Esc 关闭、遮罩点击规则、焦点约束和关闭后的焦点恢复。
- 删除类确认弹窗提供清晰标题、影响说明、取消按钮和带动作名称的危险按钮。
- 不使用浏览器原生 `window.confirm`。
- 登录失败继续使用统一的“用户名或密码不正确”，并保留密码规则帮助入口。
- 账户创建、登录、登出、收藏、分享和删除继续使用现有顶部短暂提示机制，只调整为统一视觉样式。

## 14. 响应式规则

- `>= 1024px`：推荐和收藏使用双栏工作区。
- `< 1024px`：切换为单列页面流和手机端候选交互。
- 历史页面在窄屏中从列布局转换为摘要行。
- 固定格式组件使用明确的网格、最小宽度和换行规则。
- 长地点名、地址、错误和按钮文字不得溢出或覆盖相邻内容。
- 天气信息在手机端纵向排列，不横向滚动。
- 页面标题与正文使用固定断点字号，不使用视口宽度连续缩放。

## 15. 组件边界与状态流

前端实现应沿用现有 React 结构，并将职责保持在以下边界：

- `AppShell`：全站导航、页面容器和全局反馈层。
- `SearchWorkspace`：查询前后模式、表单展开状态、当前候选和结果工作区。
- `TravelForm`：表单字段、模式切换、验证和提交。
- `QuerySummary`：查询后摘要与“修改条件”。
- `CandidateList`：桌面和手机初始候选摘要。
- `MobileCandidateSwitcher`：列表离开视口后的顶部切换器。
- `CandidateDrawer`：手机端覆盖式候选选择。
- `PlaceDetail`：地点详情的固定信息顺序。
- `DailyWeatherList`：单日与多日天气变体。
- `HistoryList`：历史记录行与溢出菜单。
- `FavoriteList` / `FavoriteDetail`：收藏列表和详情。
- `ConfirmDialog`：全站破坏性确认。

查询结果数据仍由现有 API 和状态恢复逻辑提供。本次不增加后端端点。新增的界面状态只包括当前选中地点、表单折叠状态、手机候选抽屉和顶部切换器可见性，不复制后端业务数据。

## 16. 错误处理

- 字段错误固定在字段下方预留区域，不能拉伸同一行其他输入框。
- 查询失败保留表单、权重和上一次有效结果，并在稳定位置显示错误。
- 地址候选失败不阻断自由文本提交。
- 收藏、分享、历史和账户操作失败时解除按钮锁，恢复操作前状态并显示现有顶部错误提示。
- 候选列表为空时显示原因和下一步建议，不渲染空白详情面板。
- 缺少评分时显示“暂无数据”，不转换为低分。
