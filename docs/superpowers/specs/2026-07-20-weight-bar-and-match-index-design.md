# RoamBot 比例权重条与出游匹配指数设计

## 1. 目标

解决当前三根权重滑杆彼此联动、操作不符合直觉的问题，并避免把内部排序计算包装成看似客观的“评分”。本次只调整权重交互、多人权重换算和推荐卡表达，不改变地点检索、天气、账户、收藏、历史或分享范围。

## 2. 权重交互

- 权重设置始终只向用户展示三项：天气适配、距离远近、景区热度。
- 使用一根总长固定为 100% 的比例条，内部有两个可拖动分界按钮，形成三个连续色块。
- 第一分界调整天气与距离的边界，第二分界调整距离与热度的边界；两个按钮不能交叉，可以重合，因此任一项允许为 0%。
- 比例按 5% 步长变化，三个显示比例始终为非负整数且合计 100%。
- 比例条下方固定显示三项名称、颜色和当前百分比，避免窄区段内文字溢出；比例条本身只承担空间比例表达。
- 鼠标、触摸拖动和键盘方向键都可操作。每个分界按钮提供独立的无障碍名称、当前位置和范围。
- 保留“恢复默认”，默认显示比例为天气 40%、距离 30%、热度 30%。
- 使用新的本地偏好版本键，旧版四权重偏好不自动迁移，首次进入新版时恢复默认值，避免错误解释旧数据。

## 3. 多人公平性

单人模式不使用公平性：

```text
总指数 = 天气分项 * 天气比例
       + 距离分项 * 距离比例
       + 热度分项 * 热度比例
```

多人模式把公平性作为产品固定规则，不在权重条中暴露为可调项：

```text
三项匹配值 = 天气分项 * 天气显示比例
           + 距离分项 * 距离显示比例
           + 热度分项 * 热度显示比例

总指数 = 三项匹配值 * 80% + 公平性分项 * 20%
```

前端仍向现有 API 提交四项有效权重。单人模式提交三项显示比例和 `fairness=0`；多人模式提交三项显示比例各乘 0.8，并固定 `fairness=20`。后端同步校验这一产品规则，防止其他客户端提交任意公平性权重。多人默认有效权重因此为天气 32、距离 24、公平性 20、热度 24。

## 4. 推荐结果表达

- 总值改称“出游匹配指数”，显示 0–100 的整数，用于比较本次查询中的候选地点。
- 不再使用“总分”“天气分数”“距离分数”等面向用户的文字。
- 分项数字改为定性描述：

| 分项 | `>=85` | `>=70` | `>=50` | `<50` |
| --- | --- | --- | --- | --- |
| 天气 | 非常适合 | 比较适合 | 条件一般 | 不太适合 |
| 距离 | 很轻松 | 较轻松 | 距离适中 | 距离较远 |
| 多人公平性 | 很均衡 | 比较均衡 | 存在差异 | 差异较大 |
| 热度 | 人气很高 | 较热门 | 热度适中 | 相对小众 |

- 单人结果不展示同行均衡性；多人结果展示定性描述，但不显示公平性权重或具体分值。
- 卡片显示固定说明：“指数用于比较本次候选地点，不代表官方评价。”
- 收藏、历史详情和公开分享使用相同表达；API 与历史快照仍保留数值分项，便于稳定排序和重新渲染。

## 5. 组件与数据流

- `WeightSegments` 改为组合比例条，接收显示比例并通过纯函数转换为两个累计边界。
- `formState` 负责显示比例默认值、偏好持久化以及单人/多人有效 API 权重换算。
- `TravelForm` 在提交时执行换算，不让比例条组件了解后端四权重结构。
- `ResultCard` 使用集中式定性标签函数渲染指数和分项描述，公开分享与历史复用同一规则。
- 不增加第三方 UI 依赖。

## 6. 边界与错误处理

- 拖动位置统一限制在 0–100，并按 5% 四舍五入。
- 第一边界不得大于第二边界；第二边界不得小于第一边界。
- 快速拖动、触摸离开轨道或窗口尺寸变化都不能产生负比例、总和不为 100 或 `NaN`。
- 本地偏好缺失、损坏或版本过旧时回退默认比例。
- 后端拒绝不满足单人 `fairness=0` 或多人 `fairness=20`、总和 100 的显式权重。

## 7. 验证

- 先写失败测试，证明现有三滑杆界面和旧多人默认不符合新设计。
- 组件测试覆盖两个按钮、5% 步长、不可交叉、允许重合、鼠标/键盘调整、恢复默认和三项合计 100%。
- 表单测试覆盖单人 `40/30/30/0` 与多人 `32/24/20/24` 的提交值，以及新版偏好存取。
- 后端测试覆盖多人固定 20% 公平性和非法显式权重拒绝。
- 结果卡测试断言显示“出游匹配指数”和定性描述，不再显示面向用户的“分数/总分”。
- Playwright 在桌面与移动视口验证比例条不溢出、触摸目标足够大，并完成一次推荐提交。

## 8. 不在本次范围

- 不修改内部天气、距离、公平性或热度分项算法。
- 不改变最大距离筛选、候选排序稳定规则或 coverage penalty。
- 不调整真实 API、地图、导航和行程规划范围。
- 更广泛的颜色、字体和页面视觉重构留给后续逐项界面反馈。
