# 同行计划决策工作台：整体布局设计

状态：用户批准后正式组件已实施。2026-10-07 最新验证为 Vitest 137、完整 E2E 26，通过边界及限制见 WORKBENCH_PROGRESS.md；仍待用户视觉验收，不代表 Live/公网验证。

## 1. 目标与已有问题

2026-10-07 用户批准的当日说明修订：不再内联撑高天气卡片，改为锚定原按钮的非模态小浮层，完整展示地点、日期与说明；浅青底、圆角、轻阴影。按钮/卡片/下方表格保持原位，同按钮收起、外部点击和 Escape 关闭，一次仅一个，切换日期关闭且不恢复旧浮层。优先上方，不足时下方，限制屏幕边界及高度、长内容内部滚动；桌面/手机、发起者/参与者共用。只调整前端，不改建议来源、API 或权限。

用户的根本要求是符合使用者习惯，不留大量无效空白或不对称排布。不是机械等高，也不是把所有信息塞进首屏。

当前实现让多个候选各自展开整段逐日天气，长卡片不利于同时比较；右下浮动投票覆盖候选。此前仅压缩卡片、改变左右比例并未解决结构问题。自动测试通过不等于用户视觉验收通过。

本轮重新组织已有前端，不改后端、数据库、API、评分、匿名身份或权限规则。发起者和参与者共同适用。

## 2. 内容顺序

2026-10-07 页头二次修订（优先于下方“标题右侧留空”）：用户明确旧留白不是不可改项，批准两端式Demo并要求实施。左侧标题缩小到最高1.5rem，去掉重复“城市 同行计划”，保留日期/状态/候选数量；右侧无大卡框的同行进展及下一步提示，两端同区垂直对齐，以轻分隔线连接下方工作区。手机740px以下上下排列，长标题换行不溢出。不改变下方管理/投票及日期/天气工具栏。投票分母为实际已加入人数，不是预计人数；仅从已授权返回的summary/participants推导，不可见时提示先加入/先投票，不显示虚构的0票。closed区分发起者/参与者，decided显示最终地点，ended显示留档。没有新增实时刷新、后端或API权限。

2026-10-07 用户批准的工具栏修订优先于下方旧顺序：标题、日期与状态独占左上，右侧留空；下一行左侧“比较候选地点”，右侧管理/结束投票/投票入口；再下一行左侧日期切换，右侧查看全部日期与检查天气相邻（12px）。检查时间独立放在两按钮下方，不因时间文案拉大按钮间距。桌面投票展开不挪动上方管理操作，手机按宽度自然换行并保留可收起底部投票面板。双角色共用此结构，不改变后端或权限。

1. 紧凑页头：名称、城市、日期、计划状态、已有接口允许显示的参与进度。
2. 具名工具条：日期切换、查看全部日期；发起者另有管理入口和按需检查天气。
3. 多候选比较区：同时保留所有候选，不改成只显示一个地点的主从页面。
4. 投票区：desktop 占位展开；mobile 底部面板。
5. 可查看的投票汇总：紧凑独立区域，避免无条件插在候选上方阻断阅读。

隐私说明保留可发现的简短提示，不在正文上方放大段占位卡片。加入前的昵称表单仍清晰可见，未加入者不能投票。

## 3. 候选和日期

每个候选始终显示地点名、原推荐匹配分、平均/最大路程、公平性，以及选中日期的天气图标、温度、出行建议。评分保持后端返回的原值，不受投票影响。原推荐与最近检查的时间/来源明确区分。

共享日期默认计划开始日；切换后所有候选查看同一天。某候选没有该日数据时显示“该日暂无天气记录”，不能悄悄切换到其他日期。日期条过长时局部横向滑动；不使整个页面溢出。

天气展示复用现有图标和建议含义，短概况在卡片内，完整当日说明可展开。不是把每个日期都默认铺成长卡片。推荐理由/AI 解释不显示。最新天气检查没有对应新 suitability 时显示暂无判断，不能把旧逐日建议冒充新结论。

“查看全部日期”展开统一日期明细区域，以日期为分组、候选为比较对象，不在每张卡片重复铺一份长列表。默认关闭；用户确实要读所有日期时允许页面变长。这样首屏比较与完整信息各有入口。

## 4. 排布规则

桌面比较区使用真实候选数，不补空卡、不预留空栏：

- 1 个：一张合理宽度的候选，不拉成极宽文本；其他可用位置用于真实汇总/操作，不造填充内容。
- 2 个：两张并排，指标和日期信息对齐。
- 3 个：空间足够时三张并排。候选最小可读宽度约 260px；空间不足时改为紧凑横向比较轨道并给出清楚的滚动入口，不制造 2+1 的空白格。
- 不把短候选强制拉到展开最长候选的高度。不用空白占位平衡两侧。

投票展开后重新计算比较区实际可用宽度，不能只依赖 viewport 断点。投票栏约 300～320px，位于正常 Grid 流中；候选不足最小可读宽度时采用轨道，不继续挤窄。

窄屏/手机为单列比较信息或有明确提示的候选轨道，不并排多个窄文本列；日期同步规则不变。手机投票保留底部面板，高度有限、可收起、不锁正文滚动，避免小屏同时塞入投票和三张卡片。

## 5. 投票和身份

仅保留页头“去投票/继续投票/修改投票”入口，不保留右下重复入口。打开后同一入口显示“收起投票”，面板另有关闭按钮。桌面右侧占位展开，比较区回收这部分空间；收起后归还。布局宽度与间距约 280ms 连续变化，文字不缩放；开关时保留布局 DOM、日期和草稿，不能通过整页重新挂载造成跳变。长投票表单可在专属栏内滚动，不能覆盖候选和日期工具条。手机比较区不压缩，底部面板平滑升起、高度有限、有明确收起入口；减少动画偏好下立即切换。

参与者昵称胶囊按内容适度加宽，保留足够左右留白；极长昵称可换行而不溢出。管理区“保存信息”和邀请操作在桌面共用底部基线，手机按自然顺序堆叠。相关控件对齐、间距一致，但不为机械对称添加空内容。

未提交草稿保留；选择不请求 API，明确提交才保存。提交成功收起，失败显示可重试反馈并保留草稿。键盘打开聚焦投票项、Escape 收起返回入口。busy 保持原防重复写入边界。

发起者的名称/人数编辑、邀请、同行者管理与危险操作放进按需展开的管理区，默认不占固定左栏。结束投票、决定目的地、重新开放仍为发起者可发现的操作，沿用既有确认框。管理展开影响正常文档流，不遮盖候选。

参与者不显示发起者管理操作。投票汇总仍严格先投后看；不得利用候选、页头或进度显示间接泄漏未授权票数。closed/decided/ended 时不显示可编辑投票，允许查看已有授权内容；不是只用前端隐藏来代替后端鉴权。

## 6. 组件与状态边界

- `PlanPages.tsx` 保持接口、身份和状态动作编排，分别连接 owned/public 路径。
- 新的共享比较组件负责候选集合、日期选择和完整天气区域，不访问私密出发地，不发投票/天气请求。
- 投票 UI 拆为可占位的桌面区域和手机容器，复用同一 VoteForm 与草稿状态，断点切换不能丢草稿或挂载两份可操作表单。
- 复用 `DailyWeatherList` 的图标/显示含义；若需要抽出图标，只做兼容性提取，不改变推荐主页。
- CSS 使用既有青色、浅灰、淡青变量；主色强调操作与状态，不让全部卡片大面积填色。

UI 状态仅本地：selectedDate、投票打开、管理打开、全部日期打开。加载新计划时重置查看状态；同一计划天气刷新尽量保留日期和草稿。请求失败不清掉已加载计划；无天气、长名和缺少汇总均有明确空态，不显示空的大框。

## 7. 验收与证据

前端测试：同步日期、缺日不替换、默认不铺全部日期、明细可访问、无推荐理由、投票草稿/提交/失败、断点切换、状态关闭、匿名 header 与 owner/public API 路径边界。保持已有确认与先投后看测试。

浏览器与人工检查：1/2/3 个候选，1/6 个日期，长名称，摘要/当日完整说明/全部日期，投票开关；发起者/未加入/已加入/已投票/结束状态。桌面覆盖约 1440、1280、1024，手机约 390px，至少一组短高度。

几何验收必须检查投票区与比较区矩形不重叠、没有 viewport 横向溢出、候选宽度不低于所选布局允许值、手机无桌面空投票栏、无补空卡，以及投票栏收起释放宽度。视觉截图应同时包含三候选、六日期和投票打开，不能只用二候选短数据证明三候选效果。

先使用全量 API 拦截的合成数据，避免测试写入用户演示数据库。真实后端业务 E2E 另在隔离数据目录验证并单独报告，不能与 UI fixture 验证混为一谈。过程记录真实 RED/GREEN、失败与修正，不沿用历史通过数字。
