# 本地行程中心初版验收 · 2026-10-25

## 交付范围

多轮推荐和收藏中的真实地点可加入多个行程，默认最近创建的行程；轻提示允许把刚加入的地点改投另一行程。收集不要求日期，自动分天前确定起止日期及步行、骑行或驾车。自动安排结合位置、有限道路距离及可得区域天气；不是全局最优或完整营业时间排程。

拖动当天顺序、跨天移动、移出地点只写数据库，标记路线待更新；点击更新路线才查询需要更新的路段，严格保留手动顺序。重新自动安排是独立按钮。当天地图编号与列表一致，已有道路显示带方向实线，缺失或待更新的路段仅显示虚线示意。可刷新、跨页恢复，游客登录后迁移；账号隔离、CSRF、真实来源绑定及版本冲突校验保留。

推荐卡片、收藏列表和详情均有直接加入按钮。聊天是额外调用入口，使用相同API，可创建、打开、加入、改设置、移动、移出、生成/更新及打开指定日期地图。新聊天地图入口完成隔离合同及跨页检查，没有追加真实模型测试。

## 核验依据

- API隔离数据库：三轮六地收集、重复加入、确定两天、生成、手动换序/跨天、更新不改回顺序、移出、读取恢复；游客登录迁移、退出/另一账号隔离、CSRF、旧版本与伪造来源拒绝、原子改投、收藏及聊天绑定。新增地图聊天用例验证只读打开第2天、行程文档不变。
- 路由局部5项：天气影响日期安排而不丢地点、未知道路不编造、手动顺序固定、10分钟内复用相同道路和天气、预报范围外不请求天气、改善曲折路线的基本样例。没有以此证明任意城市或大规模路线最优。
- 前端既有集中48项；末轮针对行程/地图7项、命令链10项通过。类型检查、局部ESLint及生产构建通过。最初Vitest因沙箱临时缓存rename失败未进入测试，在正常本机权限下同组通过；不计为业务失败。构建仍有原有大chunk提示。
- 浏览器8140独立数据库：三批各两地、设置日期、自动分天、鼠标拖动当天换序和跨天、显式更新、移出后刷新、多行程默认最新、轻提示改投。最初原生HTML拖动无效，改为指针捕获后真实鼠标拖动通过。拖动只产生PUT/order，显式更新才出现新增方向请求。该六地操作使用固定Provider，不能作为真实路线耗时或质量证明。
- 地图实测发现原service_host多层路径触发SDK一级路由警告，核对高德官方文档后增加根路径`/_AMapService`入口，仍复用固定上游白名单、限流、私钥注入及响应过滤，旧路径保留兼容。修正后高德底图与编号、示意线加载成功；另把已付费获得的真实结果回放至隔离数据库，实际365点道路折线及方向箭头正常显示，没有重复请求路线。

## 本地运行与边界

8034沿用live、qwen3.7-plus、open-places-v3及原数据目录。新增SQLite表为增量创建，未导入隔离验收数据到用户库。真实加载文件、冻结后端源码及HTTP构建哈希记录在`test-results/local-business-live/candidate/itinerary-refresh-20261025.json`。未部署、未改8026、未换模型、未创建子代理、未提交或推送。

最终8034监听worker1972与runtime元数据一致；15个相关后端文件逐字节匹配冻结副本，实际HTTP assets为`index-C6X6x2TX.js`、`index-D5bBqG7R.css`且与dist哈希一致。浏览器打开`http://localhost:8034/itineraries`确认新导航、创建入口及空行程页可用；8140临时进程和标签已关闭。同步及该入口读取没有调用业务Provider。

当前最多50个行程、每行程60个收集地点、自动安排最多16地、日期跨度最多30天。一次生成上限48次方向及4次天气请求，按需复用10分钟缓存；这不是本轮实际验收消耗。数据不足时显示未知/示意，不编造道路时间、停留时间或营业承诺。尚不涵盖住宿出发终点、游览时长、预约/营业时段联合排程、全局最优、长途多城独立质量证明；天气仅在可预报日期参与。
