2. 新接口 `/api/v1/assistant/commands/{catalog,proposals,execute}`。先生成方案，再校验当前页面、版本、身份与选择后执行。
3. 固定白名单执行器调用现有 API；身份取自会话，地点绑定真实历史/计划候选，不接受任意 URL、用户身份或伪造地点资料。

6. 澄清会停止后续操作；清单/候选序号以页面实际顺序为准，失效对象拒绝执行；跨页追问带最近对话。
7. 删除、清空、邀请换新/撤销、关闭/重开投票和定案需产品内确认，可输入“确认/取消”。账户密码仍由表单接收。

## 真实模型发现的改动

现有 `qwen3.7-plus` 在单轮多个 native tool calls 中实际多次只返回第一步。按 Qwen 官方说明启用多工具参数后仍复现，故改为一次原生函数调用返回最多六项有序、逐项类型化业务步骤，执行器顺序绑定新对象。

另发现模型可能使用从 0 开始的序号，或把生成邀请顺带扩展为复制链接；合同增加序号下界和明确说明，剪贴板工具仅在明确复制请求时开放。真实失败不改写为通过，原句复验结果记在验收文档。
