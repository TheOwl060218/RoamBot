# 2026-10-16 附近查询失败与设备定位接续

## 复现与定位

实际8033页面出现“苏州附近放松一下的地方 / 这轮查询尚未完成”。两次服务器日志仅有
plan_search模型HTTP200，没有后续地图/资料调用。只读检查该实例的短时规划缓存发现，两份
模型计划均设置origin=苏州、max_distance_km=5，却未附origin_quote/distance_quote。
将这两份实际输出送入隔离工作流的configure_plan，均复现ValueError原文依据缺失。
这是规划合同与地理角色错误，不是已证实的网络故障，也不是旧前端bundle导致。

## 已修改

- 在检索前纯校验规划，不触发地图或改变状态。合同错误可携带具体校验反馈纠正一次，仍
  接受相同原文校验与本轮调用预算；纠正失败不会放行检索，不无限重试。
- 只有通过校验的计划才进入v12私有短时缓存。城市中的活动范围与明确出发点分开表达，
  缺出发点时不能使用城市中心冒充当前位置。默认附近5km仍须引用“附近”原词。
- 附近请求缺必要位置时，前端直接调用浏览器设备定位API。同意后自动以原话和WGS84坐标
  继续查询，不要求先点第二个定位按钮，不重复追加用户聊天气泡。
- 已提供出发点时优先沿用该点。定位拒绝、超时或不可用时，保留重试及在聊天里说出发点
  的替代入口；新查询、停止、账户变化或卸载后，旧定位回调不能发起查询。
- 同一次想法只自动请求一次位置，防止接续异常导致重复定位/查询循环。

## 待设备验收与残余项

真实设备定位授权、精度及坐标到实际步行/骑行路线的完整推荐仍待用户设备验收。浏览器
定位需要用户授权和安全上下文（HTTPS或localhost）；桌面合成定位不能代替手机GPS。
用户拒绝授权时程序不能绕过。授权接续当前会重新提交原查询，可能有第二次模型理解，
没有把这次功能修复包装成推荐速度整体改善。开放表达的城市/出发点角色仍需更多独立
样本评价，一次模型纠正不能保证全部语义错误消失。
